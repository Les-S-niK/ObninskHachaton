# Кейс 03. Агроэпидемия: останови заражение теплицы

## Описание

Интерактивная модель распространения условного заболевания среди растений в теплице.
Пользователь задаёт начальные заражённые растения, запускает симуляцию на N условных
дней и сравнивает результаты с разными мерами защиты. Вмешательства (удаление растения,
изоляция зоны) применяются **на лету** — на любом кадре.

## Основные возможности

- Сетка теплицы минимум 10×10.
- Состояния растений: здоровое, заражено, выздоровело, удалено.
- Покадровое воспроизведение симуляции (по одному дню за шаг).
- Живые вмешательства на любом кадре:
  - **Удаление растения** — одна клетка по `coord` переходит в `REMOVED` (в любом случае,
    даже если она не заражена). Повторное удаление — no-op без стоимости.
  - **Изоляция зоны** — круглая зона (`center` + `radius`) изолируется от внешнего мира
    до конца симуляции, не удаляя растений. Оплата — разовая, только за **новые** клетки
    (пересекающиеся зоны не двойуют стоимость).
- Сравнение «без вмешательства / с вмешательством» при одинаковом `seed`.
- Воспроизводимость: вмешательства не потребляют случайные числа, поэтому при одинаковом
  `seed` поток случайности идентичен, и сценарии остаются сопоставимыми.

## Архитектура

- `src/app/service.py` — ядро: `SimulationSession` (состояние сессии + шаг + вмешательства),
  `SessionStore` (потокобезопасное in-memory хранилище с TTL), batch-функции
  `run_simulation` / `compare_scenarios`.
- `src/app/models.py` — Pydantic-схемы запросов/ответов.
- `src/app/main.py` — FastAPI-эндпоинты.
- `src/app/static/index.html` — минимальный фронтенд (покадровый просмотр, две сетки:
  baseline и с вмешательствами).

### Сессия

Состояние сессии хранится в памяти на сервере: сетка, маска изоляции, RNG, накопленные
метрики и номер текущего дня. Фронтенд запрашивает следующий кадр и применяет вмешательства
между шагами. Вмешательство изменяет текущее состояние и проявляется в **кадре N+1**
(кадр N не переписывается).

## API

### Batch (полный пересчёт)

- `POST /api/simulate/` — прогнать симуляцию целиком, вернуть все кадры.
- `POST /api/compare/` — сравнить baseline и сценарий с плановыми вмешательствами.

### Сессии (покадрово)

- `POST /api/session/` — создать сессию, вернуть кадр 0.
- `GET /api/session/{scenario_id}` — текущее состояние сессии.
- `POST /api/session/{scenario_id}/step` — продвинуться на один день.
- `POST /api/session/{scenario_id}/intervene` — применить живое вмешательство:

  ```json
  {"type": "remove_cell", "coord": [5, 5], "cost_per_plant": 10}
  {"type": "isolate_zone", "center": [2, 2], "radius": 2, "cost_per_cell": 2}
  ```

- `DELETE /api/session/{scenario_id}` — удалить сессию.

## Запуск

```bash
uv run python -m app.main
```

Откройте `http://127.0.0.1:8080/` — минимальный фронтенд для покадрового просмотра
и живых вмешательств.
